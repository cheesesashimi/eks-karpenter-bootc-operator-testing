# AI Agent Kubeconfig

This optional stack creates the `ai-agent-debugger` service account and its
cluster-wide diagnostic RBAC permissions. It then exposes a standalone
kubeconfig using the service-account token generated by Kubernetes.

It also adds the required CRD permission to the existing ClusterRole and
creates a namespaced Role and binding in `default` for the Karpenter end-to-end
test permissions. These permissions are attached to the same service account.

Apply the infrastructure and addon stacks first. The stack uses the EKS
endpoint and CA from the infrastructure state and the AWS CLI exec plugin for
provider authentication:

```bash
tofu -chdir=agent-kubeconfig init
tofu -chdir=agent-kubeconfig apply
```

The apply writes the kubeconfig to
`agent-kubeconfig/ai-agent-kubeconfig.yaml` with mode `0600`.

Test the generated configuration:

```bash
KUBECONFIG=agent-kubeconfig/ai-agent-kubeconfig.yaml kubectl get nodes
```

Override the output path, relative to this directory, with
`-var='kubeconfig_path=path/to/agent-kubeconfig.yaml'`.

The output and generated file contain a bearer token. Do not commit or share
them. OpenTofu state also contains the token and must be stored securely.

The token is a legacy service-account token Secret because it is intended to
produce a standalone kubeconfig. Delete the stack when access is no longer
needed:

```bash
tofu -chdir=agent-kubeconfig destroy
```

If the infrastructure state is stored elsewhere, pass its path consistently:

```bash
tofu -chdir=agent-kubeconfig plan \
  -var='infrastructure_state_path=/path/to/eks/terraform.tfstate'
```
